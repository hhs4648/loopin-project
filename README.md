## 초보자를 위한 MD 파일 가이드

### MD 파일이 뭔가요?

**Markdown(.md)** 은 메모장처럼 글을 쓰되, 제목·표·목록을 깔끔하게 정리하는 형식입니다.  
코드는 아니고 **설계서/기획서** 역할을 합니다. Claude Code에게 "이 문서 보고 만들어줘"라고 줄 수 있습니다.

### MD 파일 쓰는 방식 (3단계)

```
1. 생각 정리 → 2. MD에 적기 → 3. Claude Code에 "OO.md 보고 구현해줘"
```

**예시: 로그인 페이지를 만들고 싶을 때**

1. `pages.md`에 `/login` 경로, 어떤 입력칸이 있는지 적기
2. `uiux.md`에 "로그인 실패 시 빨간 토스트" 적기
3. `design.md`에 버튼 색 `#1AA7F2` 적기 (실제 Primary 색상, design.md §2.2 참조)
4. Claude Code에게:
   ```
   pages.md의 /login, uiux.md 인증 플로우, design.md 토큰을 참조해서
   로그인 페이지 구현해줘
   ```

### 언제 어떤 MD를 수정하나?

| 상황 | 수정할 문서 | 예시 |
|------|-------------|------|
| "이 기능 넣고 싶어" | requirements.md | 단어 퀴즈 기능 추가 |
| "이 화면에서 버튼 누르면?" | uiux.md | 퀴즈 완료 → 결과 화면 |
| "색깔/폰트 바꾸고 싶어" | design.md | Primary 색상 변경 |
| "새 페이지 추가" | pages.md | `/student/quiz` 추가 |
| "Figma에서 디자인함" | figma.md | Figma URL, node-id 기록 |
| "폴더 구조 바꿈" | architecture.md | `features/quiz/` 추가 |
| "Next.js로 할래" | tech-stack.md | 프레임워크 확정 |

### MD 작성 팁 (초보자용)

1. **완벽하게 쓰려 하지 마세요** — 대략 적고, 구현하면서 채워도 됩니다.
2. **`_(작성 필요)_` 부분만** 하나씩 채우면 됩니다.
3. **표를 많이 쓰세요** — Claude Code가 표를 잘 이해합니다.
4. **한 문서 = 한 주제** — 기능은 requirements, 색은 design에만.
5. **바뀌면 문서도 업데이트** — 코드만 바꾸고 문서 안 바꾸면 나중에 헷갈립니다.

### 권장 작업 순서

```
1. requirements.md  → 학습이 뭔지, 기능 목록 (✅ 1차 작성 완료)
2. uiux.md          → 학생/교사가 어떻게 쓰는지
3. design.md        → 색, 폰트, 버튼 스타일
4. figma.md         → Figma에서 디자인 (선택)
5. tech-stack.md    → Next.js 등 기술 확정
6. architecture.md  → 폴더 구조
7. pages.md         → 페이지별 상세
8. development.md   → Claude Code로 구현 시작
```
